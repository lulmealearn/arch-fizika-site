# Сайт-визитка Arch / Физика — правила проекта

Репетитор по физике, студент МФТИ (ФЭФМ). Сайт: главная-визитка, выдвижная боковая панель, хранилище интерактивных визуализаций к урокам, админка для их загрузки. Язык сайта — русский. Тон текстов — сдержанно-официальный, без сленга («домашка», «тапни») и без канцелярита. Владелец отверг и «машинный», и разговорный варианты. Исключение — приветствие на обложке, его текст задал сам владелец («Привет! Я Ахметьянов Артур Айдарович, репетитор с Физтеха…»).

## Стек и запуск
- Фронтенд: HTML + CSS + чистый JS в `public/`, без сборщиков и фреймворков без явной просьбы.
- Бэкенд: Python, FastAPI + SQLAlchemy 2, база SQLite (`storage/site.db`), на сервере планируется MySQL — код должен оставаться совместимым с обеими (никаких SQLite-специфичных фич).
- Запуск: `python run.py` (порт 8000), `--lan` для телефона, `python run.py set-password` для пароля админки.
- Владелец работает на Windows (PowerShell / Git Bash), Python 3.13. Синтаксис держать совместимым с Python 3.9 (Optional вместо `X | None`).

## Где что
- Порядок визуализаций по разделам (Математика, Механика, МКТ и термодинамика, Электродинамика, Оптика, Кванты — порядок из `sections.position`): новая визуализация и визуализация со сменённым разделом сами встают в конец своего раздела (`routes_admin._place_in_section`); кнопка «Упорядочить по разделам» (`POST /api/admin/order/by-section`) — устойчивая сортировка, внутри раздела порядок сохраняется. Ручная перестановка не ограничена.
- Админка, визуализации: порядок — перетаскиванием, стрелками или номером (поле `.pos` у строки: вписать место + Enter; в редакторе «Место в списке», для новой — сразу на нужное место; `moveTo` → `PUT /api/admin/order`).
- `public/` — единственное, что отдаётся как статика. Никогда не класть туда секреты и код бэкенда.
- `backend/app/` — маршруты: публичные в `routes_public.py`, админские в `routes_admin.py` (все под `require_admin`).
- `storage/` — база и загруженные файлы (`viz/`, `covers/`), в git не попадает.
- `seed/` — стартовые 8 визуализаций и разделы; импортируются только в пустую базу.
- Формат `/api/visualizations` = `{sections:[{id,label,color,tint,ink}], items:[{id,title,description,section,tags,parts,file,cover,access,locked}]}` — от него зависит `public/assets/js/storage.js`.
- Обложки в хранилище: загруженная через админку картинка, иначе иконка `public/assets/icons/viz/<slug>.svg`, иначе иконка раздела `_<раздел>.svg`. Иконки в манере Flaticon «lineal color»: предмет, толстый контур `#6d28d9`, плоская заливка `#c4b5fd`/`#ede9fe`, смещённая от контура; рисуются скриптом `tools/make_icons.py` (новую иконку добавлять туда же, в том же стиле).
- Визуализации отдаются с `CSP: sandbox` (без localStorage). Кнопка «← Все визуализации» добавляется при загрузке (`files.prepare_html`).

## Ученики и доступ
- Регистрация в личном кабинете `public/account/` (ник + пароль, больше ничего не храним; ник без учёта регистра; пароль ≥ 6). Восстановления по почте нет — новый пароль задаёт админ (вкладка «Ученики»), старые сессии ученика сбрасываются (`users.session_version`).
- **Занятие = папка ученика** (решение владельца): номер, тема, ссылка на запись (Телебосс/VK, может быть пустой), конспект и ДЗ в PDF (`lessons.notes_file`/`hw_file`, файлы в `storage/hw/`), визуализации (`lesson_viz`, по порядку). Отдельных «Домашек» и «Уроков» больше нет: старые ДЗ при запуске переносятся в занятие с тем же номером (`seed._migrate_homeworks`).
- Доступ выдаётся **вручную каждому ученику**: `grants` (kind = `lesson` или `viz`). Открытое занятие открывает всё в папке, включая закрытые визуализации (`access.opened_viz_ids`); `viz` — отдельная закрытая визуализация без занятия. Отметки «ученик» нет.
- Визуализация: `access` = `free` (всем без входа) или `private`. Закрытые видны в хранилище с замком и ведут в кабинет. Владелец хочет оставить бесплатными около 15.
- PDF: `/hw/<номер>` и `/notes/<номер>` — только тем, кому открыто занятие; без доступа редирект в `/account/?next=…` (с `locked=1`, если вошёл).
- Кабинет: поиск по номеру или теме (Enter открывает единственное совпадение), строка разделов «Все · Механика · МКТ и термодинамика · …» (только разделы, где есть занятия; у занятия `lessons.section_id`, по умолчанию — раздел первой визуализации в папке, в админке поле «Раздел»), под ней переключатели «Не начаты · В работе · Сданы» (повторное нажатие снимает фильтр); фильтры и поиск работают вместе; папки-карточки; окно папки `<dialog id="lesson">`, ссылка `/account/#z12` открывает занятие 12. Красный/зелёный — исключение из фиолетовой палитры по просьбе владельца.
- **Срок на ДЗ** (`deadlines.py`, решение владельца; отметки «просмотрено» больше нет): «Не начато» (красная папка) → ученик жмёт «Начать» и подтверждает → «В работе» (фиолетовая, таймер «осталось …»), срок с этой минуты — по умолчанию 3 дня, у занятия можно задать другой (`lessons.deadline_days`, поле «Срок на ДЗ» в админке; идущие сроки не меняются) → ученик жмёт «Сдал» (с подтверждением) → «Сдано» (зелёная). **До первого «Начать» материалы папки закрыты** (решение владельца: иначе ДЗ читают до старта срока): в кабинете кнопка «Начать» стоит над содержимым, вместо материалов — перечень «В папке: запись · конспект · ДЗ …» (`inside`, `locked` в `/api/me/materials`); сервер тоже не отдаёт `/hw`, `/notes`, `/watch` и закрытые визуализации этого занятия, а ведёт в папку `/account/#zN` (`access.lesson_unlocked`, `started_lesson_ids` — по `first_started_at`; админу всё открыто). После первого старта материалы остаются открытыми, в том числе после просрочки; «Сбросить срок» закрывает их снова. Срок истёк без «Сдал» — занятие **само возвращается в «Не начато»**, `overdue_count` +1 (плашка «просрочено × N»), новый срок — той же кнопкой «Начать». Проверка истечения ленивая (`settle` при каждом чтении в кабинете и админке), фоновых задач нет. API: `POST /api/me/lessons/<id>/start|submit`; админ: `DELETE /api/admin/users/<uid>/lessons/<id>/deadline` («Сбросить срок» — снова «Не начато» без просрочек). Фильтры в кабинете: «Не начаты · В работе · Сданы». Старые отметки «просмотрено» при запуске считаются сданными (`seed._migrate_viewed_to_submitted`). Админка: в строке ученика «ДЗ сданы», «ДЗ в работе», «просрочек»; в «Подробнее» — статус, срок, просрочки по каждому занятию.
- **Сдача ДЗ на сайте и проверка кураторами** (`routes_check.py`, решение владельца — вариант «куратор проверяет на сайте»): в работе у занятия вместо «Сдал» — «Сфотографировать» (только на телефоне) / «Выбрать фото или PDF», до 15 файлов; фото сжимаются в браузере до 2000 px JPEG; отправка файлов и есть сдача (`POST /api/me/lessons/<id>/submission`, только пока идёт срок; кнопка «Сдал» без файлов для занятий отключена). Файлы — `storage/submissions/<id>/01.jpg…`, тип проверяется по содержимому (JPEG/PNG/WebP/PDF), отдаются `/sub/<id>/<имя>` только ученику, кураторам и админу. Модель `Submission` (status new/checked, score/max_score, comment, checked_by, overdue — сколько раз срок истекал до сдачи, notified_at/notify_error). После сдачи фоном бот @Arch_Tutor_Bot шлёт работу (альбом фото + PDF, подпись со ссылкой `/check/#s<id>`) всем кураторам с chat id и владельцу (`ADMIN_TG_CHAT_ID`); `telegram.py` — только отправка через Bot API на urllib (обновления бота сайт не читает, бот владельца — его собственный код в другом проекте). Настройка: `python run.py set-bot` → `TELEGRAM_BOT_TOKEN`, `SITE_URL`, `ADMIN_TG_CHAT_ID` в `.env`. Ошибка Telegram сдаче не мешает — видна на странице проверки. **Куратор** = аккаунт ученика с `users.role = curator` (админ → «Ученики» → «Куратор»: галочка, chat id, «Отправить пробное сообщение»); в кабинете у него кнопка «Проверка работ». Страница `/check/` (`check.js`, `check.css`): вкладки «Ждут проверки / Проверены», фото крупно с листанием, «Верно … из …» + комментарий; результат можно изменить. Ученик видит «на проверке» / «проверено · 83%» на папке и результат с комментарием в окне занятия. Куратору открыты условия ДЗ (`/hw/N`). «Сбросить срок», «Сбросить ответы» и удаление занятия/пробника/ученика удаляют сданные работы с файлами. `submissions.lesson_id` nullable (сюда же пробники, `mock_id`); старые базы пересобираются при запуске (`seed._submissions_lesson_nullable`). **Автоочистка файлов** (решение владельца — вариант «по сроку после проверки»): файлы работ, проверенных больше 90 дней назад, удаляются (`SUBMISSION_KEEP_DAYS`, по умолчанию 90, 0 в `.env` — не удалять; непроверенные — никогда) (`routes_check.purge_old_files`, при запуске и после каждой сдачи; балл и комментарий остаются, `files_purged_at`).
- Админ в том же браузере видит всё: `/api/auth/me` и `/api/visualizations` отдают `admin`, хранилище и кабинет показывают тёмную плашку «открыта админка» с кнопкой выхода (владелец принял это за поломку приватности).

- **Пробники** (`mocks`): номер, название и вариант. **Решений нет** (решение владельца; колонка `solutions_file` не используется). Старые `/answers` и «Сдал» без файлов отключены. **Баллы пробника — первичные** (решение владельца): первая часть — автопроверка (28 первичных), вторая — куратор ставит баллы **по каждому заданию 21–26** (максимумы 3, 2, 2, 3, 3, 4 = 17 — из таблицы владельца), сумма считается сама (`submissions.task_scores`). - **Автопроверка первой части** (`mockcheck.py`): ключ `mocks.answer_key` — текст «номер: ответ», альтернативы через `|`, в скобках `2` (2 балла, одна ошибка — 1 балл; для ответов из цифр) и `любой порядок`.
