# Arch / Физика — сайт-визитка

Сайт репетитора по физике: главная, выдвижная панель, хранилище интерактивных визуализаций
и админка `/admin/`, через которую визуализации загружаются, редактируются, сортируются и скрываются.

Фронтенд — HTML, CSS и чистый JS без сборщиков. Бэкенд — Python (FastAPI + SQLAlchemy), база SQLite,
готова к переезду на MySQL.

## Первый запуск

Нужен Python 3.9 или новее. В папке проекта:

```
pip install -r backend/requirements.txt
python run.py set-password
python run.py
```

- Сайт: http://localhost:8000
- Админка: http://localhost:8000/admin/

`set-password` спрашивает пароль и сохраняет его хеш вместе с ключом сессий в файл `.env`.
Этот файл не попадает в git. Пароль можно сменить той же командой в любой момент.

При первом запуске база создаётся сама, и в неё импортируются 8 стартовых визуализаций из папки `seed/`.

### Открыть с телефона

```
python run.py --lan
```

В консоли появится адрес вида `http://192.168.x.x:8000`. Телефон должен быть в той же Wi-Fi сети.
Если Windows спросит про доступ Python к сети, разреши для частных сетей.

## Как добавить визуализацию

1. Открой `/admin/` и войди.
2. Нажми «Добавить» и перетащи `.html`. Название и объём подставятся из файла, их можно поправить.
3. Выбери раздел, теги, при желании обложку (PNG, JPG, WebP или SVG, примерно 3:2).
4. Выключи «Показывать ученикам», если это черновик: черновик видишь только ты.

Кнопка «← Все визуализации» добавляется в файл автоматически. Порядок меняется перетаскиванием
за ⠿ (на компьютере) или стрелками (на телефоне), и он же — порядок на сайте.

## Структура

```
public/                  всё, что видит браузер
  index.html             главная
  viz/index.html         хранилище
  admin/index.html       админка
  assets/css, assets/js  стили и скрипты
backend/app/             сервер
  main.py                сборка приложения
  routes_public.py       /api/visualizations, /viz/<файл>.html, /covers/<файл>
  routes_admin.py        /api/admin/... вход, загрузка, правка, порядок, удаление
  models.py              таблицы sections и visualizations
  files.py               проверка и сохранение файлов
  security.py            пароль, сессия, лимит попыток входа
  seed.py                первый импорт из seed/
seed/                    стартовые визуализации и разделы (только для первого запуска)
storage/                 база и загруженные файлы — создаётся сама, в git не попадает
run.py                   запуск и смена пароля
```

## Данные и бэкапы

Всё, что меняется через админку, лежит в `storage/`: база `site.db`, файлы `viz/` и `covers/`.
В git это не попадает, поэтому на сервере папку `storage/` нужно бэкапить отдельно (достаточно копировать её целиком).

## Безопасность

- Пароль хранится только в виде хеша (scrypt). Вход ограничен 8 неудачными попытками за 10 минут.
- Сессия в cookie с флагами HttpOnly и SameSite=Strict. Запросы к админке с чужих сайтов отклоняются.
- Визуализации открываются с заголовком `Content-Security-Policy: sandbox`: их скрипты работают,
  но не могут действовать от имени вошедшего админа. Из-за этого `localStorage` внутри визуализаций недоступен.
- Наружу отдаётся только папка `public/` плюс загруженные визуализации и обложки.

## Переезд на сервер и MySQL

1. Установить зависимости и `pymysql`: `pip install -r backend/requirements.txt pymysql`.
2. В `.env` прописать:
   ```
   DATABASE_URL=mysql+pymysql://user:password@localhost:3306/arch_site?charset=utf8mb4
   COOKIE_SECURE=1
   ```
   Таблицы создадутся сами при запуске. Данные из локальной SQLite в этом случае нужно перенести отдельно
   (или заново загрузить визуализации через админку).
3. Запускать без автоперезагрузки: `python run.py --no-reload` под systemd, а перед ним nginx:

```
server {
    server_name example.ru;
    client_max_body_size 12m;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`proxy_set_header Host $host` обязателен: по нему сервер отличает свои запросы от запросов с чужих сайтов.
